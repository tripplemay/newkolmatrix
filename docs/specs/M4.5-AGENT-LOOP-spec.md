## 1. 背景与目标

Agent 循环当前四重限制中，权力面（outbound 闸门）与例程直通为**不可让渡红线**；预算面（MAX_STEPS=5 硬编码无遥测）、视野面（人格不可循环内接力）、准备并行度（pending 逐个确认）为**可放开面**。本批在红线零触碰前提下放开后三者，交付四个产品特性：洞察深度追问、行动计划卡、一句话推进（多专家接力）、批量备好聚合确认。

**红线不变量（全批 acceptance 共同前提，违者 FAIL）：**
1. outbound 执行永过两步票据闸门——放开的一切只增加「备好」的数量与深度，不触碰「执行」
2. 任一时刻 loop 只见当值人格的工具子集（P1 时刻隔离）
3. 例程路径零 outbound 直通（本批不碰例程）
4. 行动承诺诚实条款在长链下保持（变异测试加码）

## 3. Planner 决策（P 系）

| # | 决策 | 理由 |
|---|---|---|
| P1 | **DP-3 隔离口径裁决（F-C 前提）**：隔离 = **时刻隔离**——任一时刻 loop 只见当值人格工具子集；跨人格协作经 `handoff_to`（internal，仅 orchestrator 持有）→ 落 `Handoff` 表行 → `prepareStep` 切换后续步的 system 段 + `activeTools`。**outbound 工具的人格绑定不变**（payout 永远只在 delivery 子集）。交接信封只传摘要 + 引用，新人格 system 注入「按你的 scope 重读数据，不信任交接方结论」条款（沿 Handoff 表既有语义） | DP-3 防的是越权不是协作；产品已有 Handoff 信封语义，本批只是把交接从「请求之间」搬进「循环之内」，隔离粒度不降反而显式化 |
| P2 | **遥测隐私边界**：每会话落一行 OperationLog(kind=auto)——agentId/steps/finishReason/toolNames[]/usage tokens；**不记录消息与工具入参正文**（体积 + 隐私）。fire-and-forget 但失败必须 console.error（M3-A logEvent silent-fail 教训，database-patterns §6 同族） | 观测「撞没撞上限」只需元数据 |
| P3 | **stopWhen 形态**：保持 `stepCountIs(budget)` 单上限 + loop 天然收敛（末步无 tool call 即止）；budget 挂 `AgentPersona.maxSteps`（registry 单一真相源，route 消费）。`maxDuration` 60→**120s**（10 步 × 网关 P95 需要余量；self-host standalone 无平台上限，纯配置数字） | 组合停止条件在天然收敛面前是过度设计 |
| P4 | **计划卡链路（U3）**：`propose_plan` internal 工具（模型产出结构化计划 items[{title, toolName?, needsGate, note}]，zod 校验）→ 输出 `type:'action_plan'` 走画布 type 路由 → 用户认可 = `POST /api/agent/plan-ack`（internal，OperationLog kind=auto 留痕，幂等）。**认可不解锁任何执行权**：后续逐项执行照走既有闸门（回归断言钉死） | needsGate 项卡上如实标「需你确认」= 闸门如实披露原则前移到计划态 |
| P5 | **loop 级测试床**：AI SDK 的 mock LanguageModel（`ai/test` 工具集，开工时按 7.0.31 实物核对导出名）注入缝——脚本化 tool-call 序列驱动真实 loop 机械面（handoff 切换 / 子集收窄 / pending 停驻 / 步数上限），**不依赖真网关**；模型自主决策质量留验收期真网关最小用量（L2 需授权，同 M4 口径） | streamText loop 不可 mock 网关 HTTP 层测（连接池/流语义失真）；SDK 官方 mock model 是正解 |
| P6 | **新端点 rate-limit**：`/api/agent/plan-ack` 30 req/min/IP 进程内 fail-open（复用 lib/http/rate-limit + DISABLE_GATE_RATELIMIT），沿 M4 P8 同款 | planner.md v0.9.11 硬要求 |
| P7 | **新 UI 卡片设计口径**：计划卡/聚合确认卡/人格切换标注**无 Stitch 页面级原型**（卡片级组件非页面架构变更，planner.md §2.5 评估：不新建设计稿）——必须沿既有组件语言（SurfaceCard/GateConfirm/DataTable/Toast + design-tokens），**不引入新视觉语言**；视觉基线即设计 record；既有页面（今天页/CopilotPanel）区块结构零变更，新卡只落入既有聚合位（雷达待确认区 / canvas 流） | ui-fidelity-guardrail 的精神（不自由发挥）+ 反向 guardrail（不动既有 19/14 元素类清单） |
| P8 | **F-H 渐进渲染 pre-impl 审计先行**：partial tool-input streaming 在 ai@7.0.31 + @ai-sdk/react@4.0.34 的实际支持面（配置项名/默认行为）开工前必须实物核（node_modules d.ts + 最小 poc），不支持则该 feature 降级为「工具结果分段渲染」并回报 Planner 裁决——不得按猜测的 API 写 | 铁律 1；网络资料与本仓版本可能不齐 |
| P9 | **X-Agent-Id 多人格会话语义**：响应头保留（值 = 起始人格）；**人格切换以流内 data part 事件标注**（`type:'persona_switch'`），CopilotPanel 边界卡随事件刷新。头不承载切换史（响应头是一次性的） | 流式协议的正确载体 |
| P10 | **cost-cap 不入本批**：例程 agent 化（真正的无人值守成本面）已推后，本批全部特性是人在场的交互式 loop，maxSteps + maxOutputTokens + maxDuration 三重上限够用；cost-cap 随例程批兑现（backlog 已立 BL-COST-CAP） | 范围克制；避免为未启用场景预建基建 |
