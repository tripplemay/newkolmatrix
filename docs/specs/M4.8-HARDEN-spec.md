> 批次类型:加固小批(backlog 兑现)。来源 = M4.7 复验轮三签收前提裁决(2026-08-02)+ M4.6 复验登记。

## 1. 背景与目标

两条 high 优先级 backlog 同批兑现:

1. **BL-TENANT-SCOPE-PROJECTREF**(M4.6 复验登记,M5 前必须收口):`findProjectByRef` 无 tenantId 条件,而 `copilot.projectId` 客户端可控(route.ts:66 直接取 body.context.projectId 不校验归属)——M4.6 evaluator 实测可让 system 段吐出**另一租户的项目名**。单租户 dev 下无实际影响(工具执行仍按 ctx.tenantId 作用域),但它是「新代码一律走这里」的可复用口径,任何持有 ctx 的工具复用即静默丢租户隔离。
2. **BL-LOOP-TIMEOUT-VISIBILITY**(M4.7 签收前提 S-RV2-8 + S-M47-G3-5):主 loop 撞 `LOOP_TIMEOUT_MS` 时响应体只有 start+abort+[DONE],**用户零告知、OperationLog 零行**;CopilotPanel 对流级 error/abort 无渲染分支(useChat 未解构 error,CopilotPanel.tsx:249 实证);budgetHitScope 只有 `'front' | 'none'`,子 loop 撞顶不落 OperationLog。

目标:两处租户缺口收口 + 全仓普查钉防回流;超时面「用户看得见、运维归得了因」;遥测能区分前台撞顶与专家撞顶。

## 3. 关键设计决策(全部经实物核证)

### D-1 租户收口方式:签名加参,不是内部读全局

`findProjectByRef(ref)` → `findProjectByRef(ref, tenantId)`(必选参数,不做可选——可选参数 = 留静默门)。实物:

```ts
// src/lib/agent/project-context.ts:32-39(现状,已核证)
export async function findProjectByRef(
  ref: string,
): Promise<{ id: string; name: string } | null> {
  return prisma.project.findFirst({
    where: { OR: [{ id: ref }, { publicId: ref }, { slug: ref }] },   // ← 无 tenantId
    select: { id: true, name: true },
  });
}
```

`projectContextSection(projectId)` 同步加 tenantId 参。调用链(核证 4 处,tenantId 均可达):
- `loop.ts:238`(copilot.projectId → 主 loop,ctx 在同函数作用域)
- `specialist-loop.ts:147`(subCtx.projectId,subCtx 由 `...ctx` 展开,tenantId 在)
- `loop.ts:232` / `loop.ts:262` / `specialist-loop.ts:149`(gameKnowledgeSection,见 D-2)

**跨租户 ref 的行为 = 视同不存在**:沿用现有降级纪律(project-context.ts:45-48「取名失败只写 id 不编造名」)——查不到 → 段落降级为 id-only,**名字不出现**。不抛错、不打死会话(知识段 D2 纪律)。

### D-4 超时告知镜像 onBudgetExhausted(实物先例三件套)

现状(已核证):`loop.ts:294` `abortSignal: params.abortSignal ?? AbortSignal.timeout(LOOP_TIMEOUT_MS)`(110_000,registry.ts:109);超时 → 流内只有 abort,onEnd 遥测不落行。

新增 `onLoopTimeout?: (event: { elapsedMs, agentId, steps }) => void` 回调,镜像三件套:
- **loop 层**:loop 自建 signal 时挂 abort 监听判超时;`params.abortSignal` 注入时同样监听(测试注入 30ms signal 即可驱动,RV-2b 先例)。回调失败不得打死会话(persona_switch 同款纪律)。
- **route 层**(route.ts:115 同款):`writer.write({ type: 'data-timeout_notice', data: { notice } })` + **一行 OperationLog 失败留痕**(kind=auto,只记元数据:agentId / elapsedMs / steps,**不含正文**,隐私哨兵纪律串断言)。
- **文案**:registry 单一真相源导出常量(budgetExhaustedNotice 同款),内容如实:「本次回答超时中断,已答部分如上/未能作答 + 可重试」——不假装答完(行动承诺诚实红线)。

**判据纪律(R-1 同款教训)**:只有真 abort-by-timeout 才响——正常完成、budget 截停、用户主动中断都不得误响。注入 signal 被外部 abort(非超时)时如何区分,Generator 开工时按 signal.reason 实物判(AbortSignal.timeout 的 reason 是 TimeoutError DOMException),写进测试。

### D-6 budgetHitScope 扩 'specialist'(S-M47-G3-5)

现状(已核证):`loop-telemetry.ts:54` `budgetHitScope: 'front' | 'none'`;:80 docblock 如实登记「子 loop 撞顶记在各自 consultation 产物的 budgetHit 上」(specialist-loop.ts:194)。

扩为四值 `'front' | 'specialist' | 'both' | 'none'`:主 loop 聚合本轮 consultation 产物的 budgetHit,front 撞 + 专家撞 = 'both'。**双向行为钉**(M4.7 规律 1,正反都要):专家撞顶 → scope='specialist' 落行;专家没撞 → 不得误报。docblock 同步改写(该句是 F010 类 doc 钉的锚点,改动连带核对 doc-freshness 断言)。
