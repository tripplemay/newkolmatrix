## 3. 关键设计决策

### D-1 · 扫描器改用 AST，不再修补正则（用户 2026-08-09 裁决）

**依据是实测而非偏好**：M5.1b 的复验方已用 TypeScript 编译器 API 建 ground truth，对全仓
**384 个 `.ts/.tsx` 比对出 0 分歧**，证明该路径在本仓可行；`typescript` 本就是依赖，无新增。

AST 化一次性溶掉 U1/U3/U4/U5 与「已知边界」里的多数条目（无空格写法 `import{a}from'x'` /
`import'x'`、动态 import attributes `with`/`assert`、尾逗号、字符串与模板串里的假 import）。

**遍历面（须逐个覆盖）**：`ImportDeclaration` · `ExportDeclaration`（含 `export * from` / `export * as ns from`）·
`ImportEqualsDeclaration`（`import Foo = require()`）· 动态 `import()` 调用 · `require()` 调用。

**仍抓不到、且必须如实登记的**：**运行期才能确定的路径**——`import('./' + name)`、
`` import(`./${name}`) `` 这类拼接/插值。AST 能看见调用点但看不见值；这是静态分析的固有边界，
不是判据缺陷。**该条须配一条「故意断言抓不到」的用例**，让边界有实测支撑而非只是一句声明。

### D-2 · 叙述面：删承诺句，不再加钉（用户 2026-08-09 裁决）

上一批把「叙述面守护四项」暂缓，理由是**「再加一条断言钉住上一条断言」收益递减**——两位互不通气的
evaluator 各自独立提出了这个判断。本批**不走加固路线**，改走消除路线：

> **不写承诺，就不存在「声称 > 实际」。**

`src/lib/db/*.ts` 叙述面里所有「X 守住 / 即红并点名 / 不可能再对不上 / 机械守住」类**覆盖面承诺**
一律删除，改为**纯指路**（只说钉在哪个文件，射程与盲区以那个文件为准）。

**保留** `🔒④` 现有的字面量黑名单——它守的正是「承诺句不得复活」，与本决策同向。
**不做** `🔒②b` 语义化、不扩守护面到 `runtime.ts`/`prisma.ts`：那是被判定收益递减的那条路。

### D-3 · AST 化属实现换代，回归用例必须随之重验，不得默认继承

现有回归用例是**针对正则形态**写的（如「行尾注释含引号不得整条漏抓」——AST 下该形态压根不经过
注释剥离逻辑）。换实现后它们可能**静默退化为恒真**（`audit-methodology.md` §5 点名的形态）。

**硬要求**：每一条保留下来的用例都必须重新证活——**在 AST 实现上**打一个必须让它红的变异，
红了才算数。证不活的用例要么改写、要么删除并说明理由。**不得以「它以前是活的」为由保留。**

### D-4 · 等价性审计必须用独立于被验实现的 oracle

不得「以 AST 验 AST」或「以正则验 AST」的单向对照。判据须满足：
① 对全仓 `src/` 逐文件比对新旧实现的 specifier **多重集**（不去重——去重会藏起重复捕获类假阳性）；
② 差异**逐条给出归因**（是修正 / 是回归 / 是本仓不存在的写法）；
③ 判据本身先做活性自测（正向能看见已知目标、负向对已知不该命中的不误报）。

> 本条来自 M5.1b 的六次「判据先验活救场」实录（`audit-methodology.md` §8.1）。

## 4. 承接的硬约束

1. **两道钉的分工不得互相派生**（M5.1b 反复登记）：本批只换 importer 钉的判据形态，
   `bootstrap-whitelist-census.test.ts` 的标识符判据**不动**。两者的盲区在「动态拼接」这一维**重叠**——
   该结论已在 M5.1b 实测并写进钉的文件头，本批不得把它改回「互补」。
2. **GUARDED 期望清单在本批不得变更**。AST 化若导致实测 importer 集合变化，说明换代引入了差异，
   须查明并归因，而不是改期望去迁就实现。
3. **`src/` 产品代码零改动**——除 D-2 的注释清理外，本批不触碰任何运行时代码路径。
