## 1. 本批为什么存在

前三批只证明了机制成立，**隔离本身还没生效**：

| | 现状 |
|---|---|
| 入口面 | 78 条，**已包裹 3 条**（`nav-badges` / `admin/knowledge` / `health-scan`） |
| 生产运行时 | `DB_APP_ROLE_RUNTIME` **仍未设** → 仍走特权连接，RLS 对它不生效 |
| 后果 | 24 张表的 policy 全部在库里躺着，但应用一条也没用上 |

**开关一打开，未包裹的入口会当场抛 `MissingTenantScopeError`**（fail-closed，代理分支三）。
所以「把入口包上」和「把开关打开」是同一件事的两半，缺一半等于零。

## 3. 关键设计决策

### D-1 · 两种接法都照抄已有样板，不自创

```
会话面（route handler / RSC page）        无会话面（例程 / 脚本 / webhook）
────────────────────────────────         ──────────────────────────────
withSessionTenant(({ tenantId }) => …)   withTenant(tenantId, async (tx) => …)
样板：src/app/api/nav-badges/route.ts     样板：src/lib/jobs/scheduler.ts 的 health-scan
```

**样板是实物，不是描述**：开工前逐条 Read 这两个文件，按其形态翻译，不按本段文字发挥。

### D-2 · 单租户语义不变 —— per-tenant 循环是**非目标**

例程与脚本当前只对 dev tenant 跑（`systemTenantId` / `DEV_TENANT_SLUG`）。本批**只加作用域，不改语义**：
不把「夜间筛查」改成「对每个租户各跑一次」。理由：项目当前是单租户 dev tenant（CLAUDE.md D4），
多租户例程调度是产品决策而非注入问题，属 M5.3+。

**这条要写进代码注释**：包裹点旁注明「当前只跑 dev tenant，多租户循环见 M5.3」，
否则下一个人会以为已经支持。

### D-3 · 嵌套带事务选项的处置 —— 实测**只有 1 处**会撞上，落在 F001

入口一包，领域层既有的 `withTenant` 全变成**同租户嵌套** → 复用外层事务、不开第二个（M5.1b 语义）。
但**带事务选项的嵌套会抛 `NestedTransactionOptionsError`**（嵌套不开新事务，选项无处可施）。

全仓普查（判据先验活：拿已知在场的 `gate.ts` 90s 那处证明扫描器看得见，再报数）：

```
withTenant 调用点 14 处，带事务选项 2 处：
  ⚠ src/lib/agent/gate/gate.ts:365    { timeout: 90_000, maxWait: 5_000 }
  ⚠ src/lib/jobs/scheduler.ts:94      { timeout: HEALTH_SCAN_TX_TIMEOUT_MS }
```

- `scheduler.ts:94` —— health-scan **本身就是最外层**（已包裹面），不构成嵌套，不受影响。
- `gate.ts:365` —— 在 **execute 路径**上。`/api/actions/[id]/execute/route.ts` 一旦包裹，它就成了
  带选项的嵌套 → **当场抛**。这是本批唯一的硬冲突，**必须在 F001 解决并定下处置口径**，F002–F007 照办。

**F001 须在三种处置里选一种并说明理由**（不得靠吞掉选项蒙混）：
① 把 90s 外呼移出事务（事务只包 DB 写，外呼在事务外）——最正的解，但改动面最大；
② 外层入口把该 timeout 带上（`withSessionTenant(fn, { timeout: 90_000 })`）——最小改动，
   代价是该路由的**所有** DB 操作都持有一个 90 秒事务；
③ 该路由不在入口层包，保留领域层自己的 withTenant——违背本批目标，须有强理由。

#### D-3 裁决（2026-08-10，用户）：**选 ③**，强理由是实测

审计详情见 `M5.2-F001-actions-wiring-adjudication.md`。要点：**②的真实代价不是「持有 90 秒事务」，
而是拆掉闸门的一条不变量**。`executePendingAction` 刻意是三段独立事务
（①认领 → ②副作用+收尾 → ③失败收尾），③段设计上就指望它**活过②的回滚**。
入口层一包，三段合并，③随 rethrow 一起回滚。开关开着真连 `kol_app` 实测：

```
[P2-A 作用域下沉（③）] status=failed     ticketUsedAt=已消费          failed留痕=1  irrev残留=0
      ↳ rethrow 前（事务内可见）: status=failed ticketUsedAt=已消费
[P2-B 入口层单事务（②）] status=confirmed  ticketUsedAt=null（票可重放）  failed留痕=0
```

即 ② 会让 `status='failed'` 丢失（G7 与 `f004-transaction-atomicity.test.ts:360` 钉着的那条）
且**一次性执行票变回可重放**。另：② 按本节字面写并不成立——内层不摘选项照抛
`NestedTransactionOptionsError`。M5.1b 已撞过同一堵墙并留了记录
（`tests/integration/f004-transaction-atomicity.test.ts:279-287`）。

**由此确立、F002–F007 照办的口径：**

1. 会话面入口一律按样板在入口层 `withSessionTenant`；**只有「靠后续独立事务收尾」的结构**才把
   作用域下沉到领域层。本批实测这样的地方**只有 execute 一处**——遇到第二处须重新提审，不得自行类推。
2. **新增不变量：`executePendingAction` 自带作用域，调用方不得在租户作用域内调它。**
   违反即 `NestedTransactionOptionsError` fail-closed（既有机件，不新增）。这条对 §2.1 那 9 条
   含闸门调用的探针是硬约束：**逐段包夹具与断言，不得整包 `main()`**。
3. **不改普查口径**去迁就本处置：execute route 文件本身不含包裹字面量，普查判它未覆盖——
   这是本处置的已知代价，账见 §2.3，验收时不得当作漏包。

### D-4 · 事务时长：涉外呼的入口要逐条判定，不得一包了之

把整个 handler 包进一个事务 ⇒ **事务持有时间 = 请求处理时间**。涉外呼的入口
（实测：`api/reach/refine` · `api/agent`，另加 D-3 的 execute 路径）会长时间占着连接。

**每条涉外呼入口都必须显式表态**：外呼在事务内还是事务外；若在内，timeout 定多少、依据是什么。
默认 Prisma interactive transaction timeout 是 5 秒——**不表态就是默认 5 秒，外呼几乎必然超时**。

### D-5 · 终点 = 代码包裹 + **开关开着跑通**，不碰生产（用户裁决）

验收形态是 `DB_APP_ROLE_RUNTIME=1` 且真连 `kol_app` 非特权角色下逐入口跑通。
**开关不开等于没验**：开关未开时代理走分支二（回落运行时 client＝特权连接），
漏包一个入口**数据照常返回、测试照常绿、零信号**。

**生产不动**：不设生产 `DB_APP_ROLE_RUNTIME`、不触发部署。生产切换是独立的人类闸门动作，
前置与回滚已写在 `docs/dev/deploy.md`（移除该键重启即回滚，无数据面变更）。

### D-6 · 逐 feature 独立 commit，文件集不重叠的可并行

按业务域切成 7 条实装 feature + 1 条开关面 e2e。域之间文件集不重叠 →
可按 `orchestration-patterns.md` §3 并行 subagent + worktree。**F001 必须先做完**（它定接线口径）。

## 4. 硬约束

1. **`GUARDED` 与两道普查钉的期望清单会随本批变化** —— 每条 feature 新增的 importer 若触及
   `lib/db/runtime` / `lib/db/privileged`，必须同步改期望**并说明为什么**，不得为了绿而改。
2. **不得把 `privilegedDb` 当捷径**。包不上的入口要么如实登记、要么走 D-3 的三选一；
   引入新的 `privilegedDb` 使用点 = 新开一道后门，白名单钉会红（那是它的职责，不是障碍）。
3. **每条 feature 的验收都必须在开关开着的条件下跑**（D-5），不得只跑开关未开的既有套件。
4. **`docs/specs/M5.1-uncovered-entrypoints.md` 必须随本批重跑**（`npm run census:entrypoints -- --write`），
   已覆盖数从 3 逐步涨到 47。`architecture-doc-freshness` 钉会强制这件事。
