## 5. 非阻断观察（soft-watch，不影响本轮判定）

> 均为 acceptance 未列、但机械可复现的事实，登记供 Planner 裁决是否入 backlog。**不改变 F001/F009 的 PASS 判定**（acceptance 明确枚举的分支是「正常收敛 / 撞上限 / 落库失败」三支，异常终止不在其中；且异常本身并未静默——`loop.ts:255` 与 route 的 `onStreamError` 都会 console.error）。

- **O-G1-1｜会话异常终止时不落遥测行。** 实测：注入 `doStream` 抛错的模型 → 流内出 `error` 片，`onEnd` **不触发**，遥测句柄恒 pending，OperationLog 新增 0 行。
  复现：`runAgentLoop({ model: new MockLanguageModelV4({ doStream: async () => { throw new Error('boom'); } }), ... })` → 消费 `fullStream` → 查 `OperationLog(kind=auto, summary startsWith 'agent_loop')` 计数不变。
  影响：用遥测算「撞上限率 / 步数分布」时，分母只含成功会话，网关故障率在该视图里不可见。P2 的原始目的（步数预算校准）不受损。
- **O-G1-2｜客户端中途断开的会话同族。** 未单独实测，但机理同 O-G1-1（流未消费完 → onEnd 不触发）。若后续要把遥测当作账单/可用性口径使用，需补一条「异常/中断也落行」的分支。
