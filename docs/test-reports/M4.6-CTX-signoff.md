## 8. Framework Learnings

### 新规律
- **「一红一绿」是 HTTP 链覆盖的判定式。** 声称补了「真 route 路径证据」时，只跑新用例变绿不构成证据——须打断 route 独有的那段接缝（本例 `resolveContext`），证明**新用例红、服务层用例绿**。同侧全红说明打的是共用逻辑，等于没补。
  - 来源：M4.6-CTX D1 复验（R-MUT-1）
  - 建议写入：`framework/patterns/testing-env-patterns.md §8`（「服务层测试 ≠ HTTP 链测试」条目下补判定式）

### 新坑
- **mock 了 ctx 的「真 route 用例」可能名不副实。** 本例用例 `vi.mock('agent/context')` 替换了 `buildToolContext`，若注入门恰好读 ctx 而非 route 解析产物，则整条「真 route 证据」是空的。验收必须先读码定位**门到底读谁**，再判用例有效性——不能因为文件名带 route 就采信。
  - 来源：M4.6-CTX D1 复验
  - 建议写入：`framework/patterns/testing-env-patterns.md §8`
- **黑名单式否定断言天然有上限，正向精确匹配才是根治。** D2 把 `not.toContain('（')` 升级为「6 类占位名黑名单 + 括注正则」后仍可被两种编造形态绕过（S-M46-6）；而一行正向全串匹配即可穷尽。凡「不得编造 / 不得出现」类断言，优先写成「必须恰好等于」。
  - 来源：M4.6-CTX D2 复验（R-MUT-2/3）
  - 建议写入：`framework/README.md §经验教训`
- **机械钉覆盖 N-1 段 = 留了一道静默门。** D4 的文档钉比对 4 段文档句却只钉 3 段实物，第 4 段（工具指引）挪位即静默漂移（S-M46-7）。钉子的覆盖面必须与它所守护的那句话**逐项对齐**。
  - 来源：M4.6-CTX D4 复验（R-MUT-9）
  - 建议写入：`framework/README.md §经验教训`
