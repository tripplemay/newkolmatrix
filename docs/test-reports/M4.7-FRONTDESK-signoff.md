## 3. 新缺陷（本轮发现，附复现步骤）

### RV-1 · [F009] 「逐表断言残留」被 `cleanupStep` 吞掉 —— 断言存在但**永远不会让脚本失败**（高）

**事实：** `scripts/test/frontdesk-e2e.ts:234-251` 新增了逐表清态断言，残留非 0 时 `throw`。但它被包在 `cleanupStep(...)` 里，而 `scripts/test/cleanup-step.ts:12` 的契约明写「**吞掉自身异常并喊出来，绝不向外抛**」——这正是 F011/S-RV1-1 要求并用行为级单测钉死的语义。两条正确的纪律叠在一起，结果是**断言无法影响退出码**。

**实测（隔离 worktree `/tmp/m47-rv` @ `ba7feed`，施加首轮 D-G4-6 的原变异 M-F009-1）：**

```
# 删掉 cleanupStep('handoff(projectId = 夹具项目)', …) 这一步后：
  ✓ …13 条断言全绿…
[frontdesk-e2e] ✅ 全部断言通过（零外呼 · 零真实对外副作用）
  ⚠ 清理步骤失败（不中断后续清理）：清态断言（逐表，残留非 0 即失败）
      — 清态断言失败，仍有残留：{"logs":0,"handoffs":2,"pas":0,"projects":0}
EXIT=0                                    ← 退出码没变
```

跑后 dev 库普查 `handoff: 0 → 2`，两行 `projectId` 指向已被删除的夹具项目（软引用无 FK 的孤儿行形态，M4.6 D3 原样）。**与首轮 D-G4-6 记录的结果逐字相同**，只多了一行没有任何消费者的 stderr 警告。

acceptance 原文点名的理由是「只断言 tenant 残留 = 假信心」。当前形态是**另一种假信心**：断言在场、看得见、但守不住。

- 复现：① `node --env-file=.env scripts/test/rv/rv-census.mjs` ② 删除 `frontdesk-e2e.ts` 中 handoff 那一步 `cleanupStep` ③ `npm run frontdesk:e2e` → exit 0 ④ 再普查 → `handoff +2`
- 残留已由我手工清回 0 并核证（§7）。
- 修复方向（不代做）：清态断言不能走 `cleanupStep`——它不是「清理步骤」，是**验收步骤**。放到 `finally` 末尾用独立机制记录失败并在 `main()` 返回前决定退出码（例如置 `process.exitCode = 1`），既不破坏「清理段绝不再抛」的纪律，又能让残留真的红。
