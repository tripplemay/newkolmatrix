### 5.1 缺陷

**D-G4-10 · S-RV1-2 / S-RV1-3 两条老账未收口，当初记录的绕过路径原样仍绿**
- 事实：本批给出的补救是「导出 `cleanupStep` + 行为级单测」。该行为级单测覆盖的是 **`cleanupStep` 自身的契约**（喂必抛 fn 仍 resolve / 失败要喊出来 / 前一步失败不挡后一步），它对以下两类**完全无能为力**：

  - S-RV1-3：入清单前的过滤器是个摆设（`.filter(() => true)`）
  这两条的唯一防线仍是那两条逐行/字面量正则，且**仍可被当初记录的那条路径原样绕过**。
- 因此 commit message「**S-RV1-1/2/3**（源码级正则可被写法绕过）→ …行为断言免疫写法绕过——原三条源码级正则可保留但不再是唯一防线」是**超出实物的陈述**：对 S-RV1-2/3 而言，源码级正则**仍是唯一防线**。
- 复现：`python3 scripts/test/m47-g4-mutation-driver.py M-F011-4` / `… M-F011-5`
- 定性：零产品面，纯断言强度；但 acceptance 对这一条写得极其具体（「变异含当初记录的那条绕过路径」），且这正是 `BL-E2E-CLEANUP-PIN` 立项要解决的东西 —— 半程收口若按 PASS 收，等于把老账**从「已登记待还」变成「已还」**，下一批不会再有人回头看。
