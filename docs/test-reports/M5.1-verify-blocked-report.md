## 3. 确定性真因

用户 `~/.codex/config.toml` 定义 `[model_providers.OpenAI]`，其 `base_url` 指向**自定义中转**
（非 `api.openai.com`），`auth.json` 中的 key 属于该中转。适配器的 `--ignore-user-config`
使 codex 忽略整段 provider 定义、直连 `api.openai.com` → 中转 key 必被拒。**重派多少次都一样。**

这是 M5 已记录的「认证两难」原样复现：**个人 config 依赖自定义 provider ↔ 隔离 config 即断认证**。
2026-08-05 为修「`~` 路径展开落空致崩溃」而启用的该 flag，解了崩溃，却重建了断认证。

**不能简单摘掉该 flag：** 同一份个人 config 含 `sandbox_mode = "danger-full-access"`、
`approval_policy = "never"` 与自定义指令 profile。继承它 = 派发任务拿到全权限并被未知指令改写行为，
与信封契约「契约随信封走、不依赖对方读机内任何文件」的信任模型正面冲突。
