### 1.2 MUT-A：把白名单换成扫描派生（acceptance ⑤ 明令禁止的第三条形态）

变异内容（worktree 内反向编辑，**未用 `git checkout`**）：

```ts
const BOOTSTRAP_WHITELIST: ReadonlyArray<{ file: string; reason: string }> = [
  ...deriveFromScan(),
];

function deriveFromScan(): Array<{ file: string; reason: string }> {
  return collectSources(SRC_ROOT)
    .filter((f) => usesPrivileged(readFileSync(f, 'utf8')))
    .map(toPosix)
    .filter((f) => f !== 'src/lib/db/privileged.ts')
    .sort()
    .map((file) => ({ file, reason: '自动派生：该文件实测使用 privilegedDb，发生在租户 / 会话尚不存在之前，故按扫描结果自动登记为引导点（tenant/session 尚未建立）。' }));
}
```

**变量控制（发现自己点名的陷阱）：** 理由字符串刻意做长（>30 字）且含 `租户`/`会话`/`tenant`/`session`，


### 1.5 口径问题：acceptance ⑤ 到底要求什么（以原文回答）

**F003 acceptance ⑤ 原文（`features.json`）：**

> ⑤ 白名单**恒不可从别处推导**：不读环境变量、不读配置文件、不从源码扫描结果反推——
> 「改代码才能豁免」是刻意的（沿用 tests/unit/project-scope-census.test.ts 的豁免清单范式）。

**spec D-8.1 原文（`docs/specs/M5.1-TENANT-INJECTION-spec.md:204-205`）：**

> 1. 凡「不得漏包裹 / 不得越白名单 / 不得残留」类否定断言，**必须配变异证活**：先构造一个必须让它
>    红的改动，实跑看它红，红了再还原。只写断言不证活 = 未交付（M4.6 规律 3、M4.7 三轮 4 例的直接教训）。

**判定：`requires_guard = false`。** 三条理由，全部来自原文而非偏好：

1. **⑤ 的主语是「白名单」**，谓语是「恒不可从别处推导」——约束落在**实物属性**上
   （清单是不是写死的字面量），不是「必须存在一道检测推导的测试」。
2. **⑤ 自己指定了合规范式**：`tests/unit/project-scope-census.test.ts`。实读该文件 :41-48 与 :209 ——
   该范式由「写死的字面量数组 + 旁注为什么改代码才能豁免」构成，**其中并没有任何自读源码防派生的守卫**
   （唯一相关断言是 `expect(EXEMPTIONS).toEqual([])`，即清单必须为空，而 F003 的白名单刻意非空，不适用）。
   照 ⑤ 指定的范式执行，产出就是 as-built 的样子。
3. **acceptance ④ 才是本 feature 的变异证活清单**，逐条列了三项（新建未登记文件 / 摘掉白名单一条 /
   作者未采用的 import 写法），**⑤ 不在其中**。

**因此：**

- 对 **acceptance ⑤** 而言，as-built 白名单（:46-78 字面量数组、不读 env、不读配置、不从扫描派生）
  **合规**。发现自己也这么写（「当前代码本身无缺陷」），**未把实现合规误判成缺陷**。
- 失格的是那道 **Generator 自愿多加、acceptance 未要求**的第 5 条断言：它是一条否定断言，
  无变异证活，且经 1.2–1.4 实测确实无鉴别力。按 D-8.1 的自身处置口径，它「= 未交付」——
  即**不计入交付，也不因此让 ⑤ 变成未达成**。

**这一条没有单独推翻 (a)**：(a) 的事实陈述与其自身归因（「失效的是那道闸门本身，依据 D-8.1」）都成立。
它改变的是**严重度定性**：这不是「acceptance ⑤ 未达成」，而是「多出一条绿着的假保证断言」。
危害真实（一条名为『恒不可从别处推导』的绿灯会让后人以为该面有守），但它落在 D-8.1 的交付纪律面，
不落在 features.json F003 的 acceptance 逐项面（`M5.1-TENANT-INJECTION-spec.md:274`
「acceptance 边界 = features.json 各条 acceptance 逐项」）。
