## 2. 被引用的两处既有覆盖：走的到底是哪条路径

发现方称二者「工具在写入之前就拒绝」。**读实物核对，属实。**

### `tests/integration/create-share-link.test.ts:218`

用例名：`pending→confirm 窗口内项目被删 → execute 拒 + 无 irrev 行 + 业务回滚（无 ShareLink 行）`

`src/lib/agent/tools/create-share-link.ts` `run()` 的语句顺序：

|---|---|
| :193 | `const r = await resolveShare(input, ctx);` ← 项目被删 → `:114-118` **抛错** |
| :196 | `getShareLinkService().createShareLink(...)`（mock 标记）— **不可达** |

`markerCount() === markerBefore` 在「压根没写过」时同样成立 → 对「业务写入逃出事务」零鉴别力。

### `tests/integration/payout-gate.test.ts:274`（用例起于 :246）

### 附带核实：`npm run gate:smoke` 的 G7 同样无鉴别力

`scripts/test/gate-smoke.ts:107-109` 的 `gate_smoke_failing_tool.execute` 是

## 6. 结论

**证伪失败。发现的每一条事实陈述都经实物复核成立：**

1. 被引用的两处既有覆盖确实走「写入前就拒绝」，对本病灶零鉴别力 —— 读实物证实
2. 变异在场时那两个文件 23 tests（11 + 12）全绿 —— 实跑证实
3. `gate:smoke` 整套 exit=0，含那条名字里写着「业务写入随事务回滚」的 G7 —— 实跑证实
4. 自建探针变异在场 RED（`expected 1 to be +0`）/ 还原后 GREEN —— 复现一致
5. 「产品性质正确，但完全无人守」—— 用**不新增 import** 的等价变异证实：
   全量 vitest 148/148 + gate:smoke + delivery:e2e + rls:e2e + reach:e2e **无一条翻红**
6. `NestedTransactionOptionsError` 使「外层 withTenant」判据套不到该点 —— 实跑证实

**登记一条对发现方证据链的补正（不构成证伪）：** 按发现方**字面**那条变异
（新增 `import ... from 'lib/db/runtime'`）跑全量时，`tests/unit/db-layer-importer-census.test.ts`
会红。发现方未跑全量，故不知情。但该用例是 F008 的**文档一致性钉**，它捕获的是新增的
import 语句而非原子性缺陷——把 import 换掉、语义不变，它立即恢复全绿。因此这条红
既不能替代 acceptance ③ 要求的「回滚后零残留」行为级用例，也不改变结论。

**建议 F004 判定：PARTIAL（维持）。** acceptance ③ 白纸黑字要求 7 个点**每处**至少一条
「回滚后零残留」的行为级用例；实测 6/7 达标，`gate.ts:365`（`executePendingAction`）
这一处的既有引用经查无鉴别力，缺口成立。修复面很小：把 §4 的探针补进
`tests/integration/f004-transaction-atomicity.test.ts` 即可（连同修正该文件 `:14-17`
那段「已由既有用例覆盖」的失实登记，以及 `gate-smoke.ts:484` 那条名不副实的断言描述）。
