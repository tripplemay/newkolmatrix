## 1. 发现 1(a)：侧效应 import 后跟任一 from-import → 逃逸 —— **UPHELD**

### 1.1 最小复现（纯逻辑层，不碰仓内文件）

逐位复制 `tests/unit/db-layer-importer-census.test.ts:111-133` 的 `stripComments` + `importSpecifiers`，输入即那两行：

| 输入 | `importSpecifiers()` 返回 |
|---|---|
| `import './runtime';`（控制组） | `["./runtime"]` |
| `import './runtime';\nimport { z } from 'zod';` | **`["zod"]`** ← `./runtime` 不见了 |
| `import { z } from 'zod';\nimport './runtime';`（顺序反过来） | `["zod","./runtime"]` |

### 1.2 根因（发现方归因正确，此处补完机制）

pattern-1 = `/\bimport\s+(?:type\s+)?(?:[\s\S]*?\sfrom\s+)?['"]([^'"]+)['"]/g`

关键不是「惰性」，而是**外层 `?` 是贪婪的**：正则引擎在该可选组上**优先尝试匹配一次**，只有整体失败才回退到零次。
组内 `[\s\S]*?` 虽惰性，但它会跨行扩张直到找到 `\sfrom\s+`。于是：

```
import ␣ [\s\S]*? = "'./runtime';\nimport { z }" ␣ from ␣ 'zod'
                     ^^^^^^^^^^^^ 侧效应 specifier 在这里被当作「import 子句」吞掉
```

捕获组只吐出 `zod`；`./runtime` 作为 `[\s\S]*?` 的一部分被消费，且 `re.exec` 的 `lastIndex` 已越过该区域，**不会再回扫**。
控制组之所以能抓到，是因为全文没有任何 `\sfrom\s+` 可供组匹配 → 回退到零次 → `['"]` 直接吃 `'./runtime'`。

### 1.3 端到端复现（真跑那道钉）

基线：`npx vitest run tests/unit/db-layer-importer-census.test.ts` → **10 passed**。

| 步骤 | `src/lib/db/__eval_rv2_probe_a.ts` 内容 | 结果 |
|---|---|---|
| 变异 | `import './runtime';` + `import { z } from 'zod';` | **10 passed（全绿）** —— 未登记的 runtime importer 就在 `src/lib/db/` 下，钉一声不吭 |
| 控制组 | 只留 `import './runtime';` | **1 failed / 9 passed**，报文逐字点名：`多出（未登记的 importer）：src/lib/db/__eval_rv2_probe_a.ts` |

控制组的意义：同一个**未 commit 的新文件**、同一路径、同一模块目标，只差一行 `from`-import。
这同时排除了两个反向解释 ——（i）「扫描器没扫到这个文件」；（ii）`framework/patterns/testing-env-patterns.md` §11「`git grep` 只搜已跟踪文件」（该钉用 `readFileSync` 递归，未跟踪文件照扫，控制组的红即证）。

**384 / 2 / 5 三个数字全部吻合。** 且这两处是真实产品代码的**寻常写法**（`AppWrappers.tsx:3-4,7-8` 四条 CSS 侧效应 import 夹在 `react` 与 `contexts/...` 的 from-import 之间），不是构造出来的形态——这条逃逸路径在本仓是**已在发生**的，不是假想。

## 2. 发现 1(b)：反引号动态 import → 逃逸 —— **UPHELD**

### 2.1 端到端复现

| 步骤 | `src/lib/db/__eval_rv2_probe_b.ts` 内容 | 结果 |
|---|---|---|
| 变异 | `const m = await import(` + 反引号 `./runtime` 反引号 + `);` | **10 passed（全绿）** |
| 控制组 | 只把反引号换成单引号 `import('./runtime')` | **1 failed / 9 passed**，点名 `多出（未登记的 importer）：src/lib/db/__eval_rv2_probe_b.ts` |

根因直观：pattern-2 = `/\bimport\s*\(\s*['"]([^'"]+)['"]\s*\)/g` —— 字符类 `['"]` **不含反引号**。

### 2.2 该形态是真实 import，不是语法噪声

独立运行时验证（`node` 跑纯 ESM）：

```
$ node .../bt/main.mjs
backtick dynamic import 运行时有效： loaded-via-backtick
```

无插值的模板字面量在 ESM 里就是普通字符串，反引号动态 import 与引号动态 import 运行时完全等价；TypeScript 亦按静态 specifier 解析。**这是一条能真正拿到运行时 client、却对钉不可见的路径。**

### 2.3 「已登记边界只写了字符串拼接」—— 引用属实

`tests/unit/db-layer-importer-census.test.ts:24-25` 原文逐字：

```
// 已知边界（如实登记，非本批解决）：字符串拼接出来的动态路径
// （`import('./' + name)`）扫不到。本仓 db 层无此写法，见文件末的活性证明。
```

登记面 = **字符串拼接出来的动态路径**。反引号包裹的**静态**路径既不是拼接、也不是动态路径，**不在登记内**。发现方的引用准确。

### 2.4 邻接风险属实

`src/instrumentation.ts:22-25` 逐字：

```ts
    const [{ getRuntimeDb }, { runConnectionRoleSentinel }] = await Promise.all([
      import('./lib/db/runtime'),
      import('./lib/db/app-role'),
    ]);
```

本仓**唯一**以动态 import 引 `lib/db/runtime` 的地方现用单引号。把引号改成反引号是一次风格中性、review 极易放行的编辑，改完这道钉对 `instrumentation.ts` 当场恒盲（且 GUARDED 期望里还列着它 → 会变成 `missing` 红）。发现方的邻接指认成立。

### 3.4 它是否证伪了 `tenant-scope.ts:51` 那句话？

该行原文（上下文 `:46-51`）：

> 上一版写「三条已被实测证伪的绝对句不得复活」，而黑名单拍平成三个字符串后，其中两个同出首轮第 ③ 条，而第 ① 条（关于「单层」那句）实际无人守 …… **同一个缺陷族在为消灭它而写的那句话里复发了一次**，故现在改成 claim → patterns 的结构：**条数就是数据结构本身，声称与实际不可能再对不上。**

**证伪成立。** 该句自陈要消灭的「缺陷族」是「声称的覆盖面 > 实际覆盖面」（上下文逐字点明「第 ① 条实际无人守」）。本次变异复现的正是**同一族**：CLAIMS 里 ① 条赫然在列（声称守 3 条），实际只有 2 条能命中（实际守 2 条），而全仓无一条断言会红。
换的只是机制——上一版是「两个 pattern 同出一条」，这一版是「pattern 变成死码」。
若把该句按最窄字面读作「整数 3 不会变」，那它确实为真，但那样它就不再是它所在段落声称的那个防线，且与前文「声称与实际」的所指自相矛盾。故按其自身语境读，该句为假。

## 4. 关键判断：`runtime.ts:17-19` 那句话是否为假？

原文逐字（`src/lib/db/runtime.ts:17-19`）：

> 其余任何 src/ 文件 import 本模块都等于绕过 ALS 注入面。该清单由
> tests/unit/db-layer-importer-census.test.ts 机械守住（**新增 importer 即红并点名**），
> 不再依赖本注释自觉。

**判定：该句为假。** 理由：

1. 括号里的「新增 importer 即红并点名」是一条**全称保证**，没有任何限定词（不限形态、不限写法）。
2. 至少两种**真实且运行时有效**的 import 形态可以新增一个 `src/lib/db/runtime` 的 importer 而钉全绿（§1.3、§2.1），均有控制组证明不是扫描器没看见。
3. 该钉自己的「已知边界」段（`:24-25`）**只登记了字符串拼接动态路径**，未登记这两种形态——即这两个洞不属于「已如实登记的射程外」，而是**保证与实际不符**。
4. 反证一句该句能成立的读法：若把它读作「以 from-import / 引号动态 import / re-export 形式新增的 importer 即红」，那它就是真的——但注释里没有这个限定，且 `runtime.ts` 本身正把这句话当作「可以不再依赖注释自觉」的理由（「不再依赖本注释自觉」），其效力恰恰取决于全称性。

**补充定界（对发现方有利也有不利的部分都写）：** 该钉当前输出的两份 GUARDED 清单**没有错**——§1.4 实测被吞的 5 个 specifier 全是 CSS，`src/` 下当前**不存在**以逃逸形态引 `runtime` / `privileged` 的文件。所以这不是「清单此刻已失实」，而是「清单的**守护保证**此刻已失实」。F008 的任务恰恰是「把失实注释改对」，而它改对注释后写下的那句机制保证本身失实——同一缺陷族第三次复发。
