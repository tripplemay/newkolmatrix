### 3.1 发现 1（驱动 PARTIAL）—— importer 钉的「新增 importer 即红并点名」不成立

`src/lib/db/runtime.ts:17-19` 写着：

```
// 其余任何 src/ 文件 import 本模块都等于绕过 ALS 注入面。该清单由
// tests/unit/db-layer-importer-census.test.ts 机械守住（新增 importer 即红并点名），
// 不再依赖本注释自觉。
```

**两种真实 import 形态可以逃过它（都不需要动任何测试文件）：**

#### (a) 侧效应 import + 其后任一 `… from '…'`

新建 `src/lib/db/__eval_rv2_probe_sideeffect.ts`：
```ts
import './runtime';
import { z } from 'zod';
```
→ `npx vitest run tests/unit/db-layer-importer-census.test.ts` → **10 passed（全绿，不红不点名）**

**判据活性已证（`audit-methodology.md` §8）：** 同一文件只留 `import './runtime';` 一行
→ **1 failed，报文 `多出（未登记的 importer）：src/lib/db/__eval_rv2_probe_sideeffect.ts`**。
即扫描器**看得见**该文件，绿不是空洞绿；损耗来自正则本身。

**根因（`tests/unit/db-layer-importer-census.test.ts:124`）：**
```js
/\bimport\s+(?:type\s+)?(?:[\s\S]*?\sfrom\s+)?['"]([^'"]+)['"]/g
```
`(?:[\s\S]*?\sfrom\s+)?` 是**贪婪可选 + 惰性跨行**：从第一个 `import` 起会一路吃到后面第一个
` from '`，把中间的 specifier 连同 `import` 关键字一起吞掉，`lastIndex` 随之跳过。
于是「侧效应 import 的那个 specifier」永远读不到。

**这个损耗在本仓是活的，不是假想形态。** 我写了一个探针，把该钉的 `stripComments` /
`importSpecifiers` 逐字复制出来，与一个逐行解析的严格判据对比全 `src/`：

```
[rv2-probe] src 文件数= 384
[rv2-probe] 有 specifier 被吞的文件数= 2
[rv2-probe] 明细= [
 { "file": "src/app/AppWrappers.tsx",
   "missing": ["styles/App.css","styles/Contact.css","styles/MiniCalendar.css","styles/index.css"] },
 { "file": "src/components/calendar/MiniCalendar.tsx",
   "missing": ["react-calendar/dist/Calendar.css"] } ]
[rv2-probe] 最小复现 钉看到的= ["zod"]      严格判据看到的= ["./runtime","zod"]
[rv2-probe] 单行侧效应 钉看到的= ["./runtime"]
```

今天被吞的 5 个都是 css 路径（对被守护模块无害），**但机制是通用的**：
`import 'server-only'` 这类 Next.js 常见写法一旦出现在 db 层模块顶部，其后的 import 就开始漏。

#### (b) 反引号动态 import

新建 `src/lib/agent/__eval_rv2_probe.ts`（**刻意放在 `src/lib/db/` 之外** —— runtime.ts 那句话
说的正是「其余任何 src/ 文件」）：
```ts
export async function probeLoad() {
  const m = await import(`../db/runtime`);
  return m.getRuntimeDb();
}
```
→ `npx vitest run tests/unit/db-layer-importer-census.test.ts` → **10 passed（全绿）**

**对照（活性自证）：** 同一文件只把反引号换成单引号 →
**1 failed，报文 `多出（未登记的 importer）：src/lib/agent/__eval_rv2_probe.ts`**。

**根因：** 动态 import 的 pattern（`:125`）只认 `['"]`，模板字面量不认。
该文件 `:24-25` 登记的已知边界是「**字符串拼接**出来的动态路径（`import('./' + name)`）」——
反引号**静态**路径不是字符串拼接，不在已登记范围内。而 `src/instrumentation.ts:22-25`
现在就是用动态 import 引这个模块的，改写成模板字面量是很自然的一次重构。

#### 口径说明（如实标注未验项）

* 「只跑被守护的那一个钉」这一层证据是**完整**的：钉全绿、控制组红并点名，两次对照同位置同形态。
* 「**全仓**无一条会红」这一层：把探针放在 `src/lib/db/` 下时，`architecture-doc-freshness`
  的另一道钉会因「新增 db 层模块未登记进 architecture.md」而红——**那不是 importer 钉抓到的**，
  是另一件事（任何新 db 模块都会红，与它 import 谁无关）。把探针挪到 `src/lib/agent/` 可绕开
  这一干扰，但该配置下的全量跑正是 §1.2 的卡死点，**全量证据未取得，如实登记为未验**（§7.1）。
  这不影响发现 1 的成立：被点名的那句话说的是「该清单由**这道钉**守住」，而这道钉确实没红。
