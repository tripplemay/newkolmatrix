## 2. 「两个 src 文件仅注释」的独立核实

Generator 在 handoff 里称 `src/lib/db/tenant-scope.ts` 与 `src/lib/db/prisma.ts`
「仅注释、零运行时代码路径」。**该陈述是被验对象的自述，不作为通过依据**（铁律 13）。以下是我自己的判据。

### 2.1 判据：TypeScript **scanner token 流**比对（非上轮的 emit 比对）

```js
ts.createScanner(ts.ScriptTarget.Latest, /* skipTrivia */ true, ...)
// skipTrivia=true ⇒ 空白与**全部注释**被扫描器丢弃；
// 逐 token 比对 (SyntaxKind, tokenText) 序列。
// 序列完全一致 ⇒ 两版之间的差异只可能是注释/空白，不可能改变运行期语义。
```

判据脚本置于 scratchpad（**未落 `scripts/`**，避免污染 doc-freshness 的普查计数）。

### 2.2 判据先验活（5 个探针，全部方向正确）

| 探针 | 构造 | 期望 | 实测 |
|---|---|---|---|
| P1 | 旧文件 + 纯新增注释（行注释 + 块注释） | true | **COMMENT_ONLY=true** |
| P2 | 单 token 运算符翻转 `===` → `!==` | false | **false**，点名 `token #119 EqualsEqualsEqualsToken → ExclamationEqualsEqualsToken` |
| P3 | 自身对自身 | true | **true** |
| P4 | **字符串字面量内部**改字 `'@prisma/client'` → `'@prisma/clientX'` | false | **false**，点名 `token #7 StringLiteral` |
| P5 | 整条语句删除 | false | **false**，`token count 136 vs 124` |

> P4 是刻意设的：注释与字符串「长得都像文本」，判据若把字符串一并当 trivia 丢掉就会瞎。实测不瞎。

### 2.3 正式判定

```

src/lib/db/tenant-scope.ts  -> COMMENT_ONLY=true  tokens=236/236 :: identical token streams
```

**并在这两个文件本身上再验一次活**（防「判据对这两个特定文件恰好失灵」）：

```
prisma.ts    + 1-token 翻转 (===→!==)  -> false, token #119 差异
tenant-scope + true→false             -> false, token #233 TrueKeyword → FalseKeyword
```

### 2.4 附加检查：有语义的注释

注释并非一律无害（`@ts-ignore` / `@ts-expect-error` / `eslint-disable` / `webpackChunkName` /
`__PURE__` / `prettier-ignore` / 三斜线指令 / 覆盖率 ignore 均会影响工具链）。
对本轮**新增行**逐类 grep：

```

```

**判定：`src_changes_comment_only = true`。**

> **一条必须说清的边界：** 「仅注释」= 零运行期语义变化，**不等于**「零测试可见」。
> `tests/unit/db-layer-importer-census.test.ts`（F008 的钉）**按文本**扫这两个文件，注释对它是承重的。
