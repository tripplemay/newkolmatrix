### 2.1 **新假阴（fix-3 引入的真实退化）：`import` 与 `from` 之间出现引号 / 反引号 / 分号即整条漏抓**

`stripComments` 只剥**整行** `//` 注释，故**行尾注释**会原样进入正则输入。新 pattern 把
from 之前的区域收紧成 `[^'"\`;]*?`，于是行尾注释里的一个 `'`、`` ` `` 或 `;` 就切断匹配。
OLD/NEW 对照（同一 `stripComments`，只换 pattern）：

| 合法写法 | OLD | NEW | 判定 |
|---|---|---|---|
| `import {\n a, // it's fine\n b,\n} from './x';` | 抓到 | **漏** | ❌ fix-3 新引入 |
| ``import {\n a, // 见 `runtime`\n b,\n} from './x';`` | 抓到 | **漏** | ❌ fix-3 新引入 |
| `import {\n a, // foo; bar\n b,\n} from './x';` | 抓到 | **漏** | ❌ fix-3 新引入 |
| `import {\n a, // 见 "runtime"\n b,\n} from './x';` | 抓到 | **漏** | ❌ fix-3 新引入 |
| `export {\n a, // it's\n} from './x';` | 抓到 | **漏** | ❌ fix-3 新引入 |

严重度：本仓注释**大量使用反引号引用标识符**（`runtime.ts` 文件头本身就是这种写法），
多行 import + 行尾反引号注释是完全普通的编辑。该类退化**未登记**在「已知边界」段。
（缓解事实：当前 `src/` 三个真实 importer 均为单行 import，故此刻清单输出仍正确
——**失实的是覆盖面，不是当下的清单**，与 rv2 的定界同构。）

### 2.2 旧疾且未登记：动态 import 带 import attributes

`await import('./x', { with: { type: 'json' } })` 与 `assert` 版本 —— **OLD / NEW 都漏**。
