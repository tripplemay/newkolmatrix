### D-2 —— 一条回归用例的输入不复现它自称的旧缺陷

`db-layer-importer-census.test.ts` 的
`🔒 回归：CJS require 与「后文任意字符串含 from」两种形态` 里第二条断言：

```ts
expect(
  importSpecifiers("import './runtime';\nconst s = 'a from b';"),
  '后文普通字符串里的 from 又把侧效应 specifier 吞掉了',
).toContain('./runtime');
```

逐条实测（对同一输入分别跑 OLD / NEW）：

```
T3-b 后文普通字符串含 from   OLD=true  NEW=true  → ★死钉：OLD 下也绿，不钉本轮修复★
```

原因：OLD 的 `\sfrom\s+['"]` 要求 `from` + 空白后**紧跟引号**；`'a from b'` 里 `from ` 后面是 `b`，
匹配失败 → 回溯到可选组为空 → `./runtime` 照样抓到。

它自称的那个「加宽」**本身是对的，只是这个输入不触发它**。能真触发的形态我找到了：

```
'a from ' + 'b'（两个字符串）  OLD=[" + "]  → ★漏掉 ./runtime★   NEW=["./runtime"] → 抓到
两条侧效应 + 后续 from-import   OLD=["zod"]  → ★漏掉 ./runtime★   NEW=[…三条齐] → 抓到
```

**影响：** 该断言无害（NEW 下成立），但它**不钉任何东西**，而其行内注释与失败信息断言了
一件对该输入不成立的事。同一用例的第一条（CJS require）是真回归钉（OLD 下红）。
逐条清点该三个新用例的 9 条断言：**3 条是真回归钉**（T1-a 侧效应 / T2-a 反引号 / T3-a require），
**5 条是刻意的反向护栏**（T1-b/c/d、T2-b：「防止修法把另一头改瞎」，源码已如此自述，属正当），
**1 条是 D-2**（T3-b）。归属 F008。
