## 2. 台子本身可靠吗 —— probe-bench **判据可靠，但自测有一处盲区（已由本轮补上）**

交付方 `m51c-f001-probe-bench.mjs` 的活性自测是两道：
正向（已知分歧输入 `import{a}from'./no-space';` → 换代前各代必须 `[]`、AST 必须抓到）、
负向（一致输入 `import { a } from './plain';` → 两侧都必须 `['./plain']`）。

这两道能拦住的失效模式：台子把所有代都加载成 AST 版（正向会炸）、`run` 恒返回 `[]`（负向会炸）。

**盲区：** 若 5 个世代**全部坍缩成同一个换代前实现**（例如 `gitShow` 取错 rev），两道自测**都会通过**，
而所有「N/5」会退化成「0/5 或 5/5」——恰好是本批要判的那个量。故本轮**加了第三道**：
取一个已知具有区分性的输入，要求各代取值**不全相同**。

```
[自测] 正向 OK  负向 OK  世代未坍缩 OK
       区分性输入上各代取值：6a120a7=["./ap"] fadc1f4=["./ap"] 1ea4abb=[] 2bc02aa=[] c251fe9=["./ap"]
```

坍缩盲区**实测不存在**（各代取值确实不同）。交付方的数字不受影响，但自测强度差这一道，
已在本轮工具 `tests/tools/rv1/rv1-independent-bench.mjs` 中补齐并留仓。

## 4. 变异台可靠吗 + 变异计数独立重算

### 4.1 台子判据审查（`m51c-f001-mutations.mjs`）

它防「台子坏了却报全绿」的机件有三道，逐道审：

| 机件 | 拦得住什么 | 判定 |
|---|---|---|
| 基线必须全绿（否则 `exit 2`） | 拿一个本来就红的文件去打变异 | 有效 |
| 锚点必须**恰好命中 1 次**（否则记 `skip` 并打 ⚠） | 锚点写错时**不会**冒充「全绿」 | 有效，这是关键一道 |
| 还原后 sha256 必须回基线（否则 `exit 3`） | 变异残留污染后续 | 有效 |
| **三种红法分流**（assert / file / pass，按退出码兜底） | 首轮那个假阴性（收集期抛 → `Tests no tests` → 被当成 0 failed） | 有效，坑已写进代码 |

**查出一处缺口（不影响本轮任何数字，登记）：** 台子**不校验「变异是否真的改变了文件」**。
若某条的 `from` 与 `to` 写成了等价文本，`replace` 成为空操作，该条会被报成 `⚠ 全绿` ——
外观与「真·已登记盲区」无法区分。本轮工具补了这道（写盘后若 `sha === baseline` 立即 `exit 4`）。

由于 M10 是全表**唯一**报「全绿」的一条，这道缺口恰好落在它身上，故对 M10 单独手工复核（见 4.3）。
