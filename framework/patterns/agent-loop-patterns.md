# Agent Loop Patterns — 多步 agent 循环的可测性与断言强度（v1.0.13）

> **触发条件：** 实装或验收「模型多步调工具」的 loop（AI SDK `streamText` + `stopWhen` / 子 loop / 人格接力 / 步数与墙钟预算 / loop 遥测）。
> 单次 prompt→JSON 的 AI action 不适用本文件，见 [ai-action-contract.md](ai-action-contract.md)。
>
> 来源批次：KOLMatrix M4.5-AGENT-LOOP · M4.6-CTX · M4.7-FRONTDESK（三批共 5 轮验收 + 3 轮复验的实证）。

---

## 1. loop 的机械面必须离线可测：用 SDK 官方 mock model，不要 mock 网关 HTTP 层

**做法：** 把 loop 装配抽成带 `model` / `ctx` 注入缝的函数（KOLMatrix：`lib/agent/loop.ts` 的 `runAgentLoop`），
测试床用 `ai/test` 的 `MockLanguageModelV4` 脚本化 tool-call 序列驱动**同一个**装配函数。
于是步数上限截停 / 工具子集收窄 / outbound pending 停驻 / 人格接力切换全部离线可断言，零外呼。

**关键是测试床与生产共用同一装配函数——在测试里复刻一份 loop 必然漂移。**
「与生产同款 loop」应由「共用同一函数」保证，不由人工比对保证。

**注入缝纪律（M4 实证）：** `model` / `ctx` 一旦传入就**无条件使用**，不得因凭据缺失把注入的 model
改道回默认 caller——否则无凭据环境（CI）下 mock 测试静默走进降级分支，测的不是被测对象。
详见 [testing-env-patterns.md §10](testing-env-patterns.md)。

**已知局限（必须如实登记为 L2）：** mock model 发的是完整 `tool-call` 片、**不发 `tool-input-delta`**，
故「入参流式渲染」这类特性离线只能测分支判定，真流表现仍归 L2。

**来源：** KOLMatrix M4.5-AGENT-LOOP F009（`tests/support/agent-loop-testbed.ts`）。

## 2. mock 测试床把工具入参写死 → 系统性掩盖「模型能否自己发现入参」类缺陷

**反面案例（代价最大的一条）：** M4.5 以 11/11 PASS 收尾，**上线首轮真实对话就撞到**
「模型反问用户要 projectId」——因为 `ctx.projectId` 服务端已解析但从不进 system 段，
而 13 个工具把它当模型入参。测试床里所有 tool-call 的 input 都是脚本写死的
（`input: { projectId: fx.id }`），模型从不需要「自己发现」任何入参，
于是这条缺口落在测试床的**结构性盲区**里，11 条 acceptance 也无一要求
「模型能在项目页自动认到当前项目」。

**规律：** 凡「模型需要自己填的入参」，测试床验不到。必须二选一：
1. 在 acceptance 里单列一条**装配层断言**——system 段里到底有没有它（离线可验）；
2. 明确留给 L2 真模型验，并登记为未验证面（不得当作已验证）。

**推论：** 「测试床全绿」对这一类缺陷不构成任何证据。拆 features 时，
凡涉及「模型自主性」（自己发现入参 / 自己选专家 / 自己决定要不要咨询）的 acceptance，
都应显式标注它归 L1 的哪一层还是归 L2。

**来源：** KOLMatrix M4.6-CTX（生产实测缺陷，根因分析）。

## 3. as-built 陈述必须钉成**双向**行为——只钉一个方向 = 半个钉子

**反面案例：** M4.7 的预算口径是「**接力**到深链专家抬预算，**咨询**不抬」。
第一次修复只改了文档措辞，复验实测：删掉 `budgetChain.add(target)`（接力抬的实现）后
**没有一条用例会红**——`chainBudget()` 的函数级用例只证明函数本身对，
证不了它被接在接力分支上。
补了「接力 → 跑满深链档」的 loop 级用例后，复验轮三又加测**反方向**：
把「咨询也抬预算」写进 `prepareStep` → RED(3)。

**规律：** 形如「A 会 X，B 不会 X」的 as-built 陈述，必须**两个方向各一条行为级用例**：
- 正向：A 发生时 X 真的发生（删掉实现 → 红）
- 反向：B 发生时 X 真的不发生（把 X 加到 B 上 → 红）

只钉正向，等于允许别人把 X 扩大到 B 而无人察觉；只钉反向同理。
**判据自检：** 写完问一句「文档里这句话的**否定半句**，谁在守？」——答不上就是半个钉子。

**来源：** KOLMatrix M4.7-FRONTDESK 复验轮二 RV-4 / 轮三 §22.1。

## 4. 「默认闸」必须有两样钉：在不在 + 读不读常量

**反面案例：** M4.7 给子 loop 与主 loop 各加了墙钟闸（`AbortSignal.timeout(常量)`），
但仓内每条超时用例都**注入**短闸，没有一条走生产默认路径——
摘掉两个默认 `AbortSignal.timeout` 后 1414 条全绿。
补第一样钉（让 mock 捕获它**实际收到的** `abortSignal`，不注入时必须非空）之后，
复验又发现第二样缺席：把默认闸**写死成常量当前的值**（`45_000`）→ 仍然全绿。

**两样钉分别是：**

| 钉 | 判据 | 对应变异 |
|---|---|---|
| **在不在** | mock 捕获实收的 `abortSignal`，生产默认路径下必须非空 | 摘掉默认闸 → 必须红 |
| **读不读常量** | `vi.doMock` 把常量换成极小值（如 30ms），断言 abort 时刻**跟着走** | 默认闸写死数字（取值不变）→ 必须红 |

**第三样（可选但常被忽略）：取值的下界护栏。** 不等式类约束（`N × 子闸 < 主闸`）
只挡**放大**方向；把常量改小到荒谬值（45s→3s）不会有任何钉子响。
若该常量将来要按线上数据校准，请补一条下界断言，并在注释里如实写明
「这是护栏不是实测值，下调须带数据一并改」。

**来源：** KOLMatrix M4.7-FRONTDESK 复验轮二 RV-2 / 轮三 §22.2。

## 5. loop 遥测是 fire-and-forget → 测试必须有确定性等待，且等待要**下沉到测试床**

**坑：** 遥测落库发生在 loop 调用返回之后的几毫秒内（`onEnd` 里 `void log(...).then(settle)`）。
测试若不等它就进 `afterAll` 删租户：
- 慢机上会被**删后迟到**的那一行打红（CI 假红）；
- 或更糟——删得比它快，留下一行**孤儿行**（`tenantId` 指向已不存在的租户），断言绿但库脏。

**做法：** loop 装配返回一个 `telemetry: Promise`**专供测试确定性等待**（请求路径不得 await 它）。
关键是**把 await 下沉到测试床**（`runScriptedLoop` 内部），而不是逐文件补——
M4.7 实证：逐文件补只覆盖了 2 个文件，同族竞态在第三个文件仍被抓到翻红。

**例外要显式：** 注入了自定义 telemetry writer 的用例不落库，没有孤儿行可言；
其中往往有一条**专门证明「writer 永不 resolve 也不阻塞会话」**——
无条件 await 会把那条正面证明变成死等。故条件应为「只在走默认 writer 时等」。

**验收口径：** 「测试绿」不等于「没漏行」。请连跑 ≥10 次全量并核**孤儿行净增为 0**。

**来源：** KOLMatrix M4.7-FRONTDESK S-RV2-10 / 复验轮三（13 次全量跑净增 0）。

## 6. 人格 / 工具子集隔离必须有**两道**防线，且执行侧那道要单独有钉

**做法（M4.7 as-built）：** 视野收窄（`activeTools`）只影响模型看见什么；
**执行侧必须自己挡**——否则模型凭历史消息里的工具名照样能调到别的人格的工具。
两道防线各自要有变异证明：短路执行侧那道 → 必须红。

**推论：** 「模型看不见它」不是安全边界，「调了也拒绝」才是。
凡涉及 outbound / 不可逆动作的工具，隔离断言必须打在执行侧。

**来源：** KOLMatrix M4.5 F005 时刻隔离 + M4.7 F001（复验 MUT-1 证活）。
